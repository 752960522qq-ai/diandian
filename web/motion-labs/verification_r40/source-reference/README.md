# R40 原里昂持筒源动作核对

只读核对用户提供的 w07_000.fbx / w07_001.fbx / w07_002.fbx。所有输出由这些 FBX 的实际姿态矩阵导出，不是生成式参考图，也不是原游戏截图。未修改生产代码。

## 源数据与手型边界

- Idle：1–2 帧；Walk：1–19 帧；Run：1–14 帧，按现有重定向脚本的 30fps 基准。
- 三者都包含 Leon_SkinnedMesh 和 22 根骨骼。源无独立手指骨；左右手末端分别为 Bone_13_HandNegativeX / Bone_16_HandPositiveX。
- 因此不能从此源提取独立的里昂手指弯曲动画。现有重定向脚本固定采用目标角色 RifleAimingIdle 的手指旋转，不等于复用了里昂手指。
- 参考图 source_skeleton_reference.png 是真实骨骼矩阵的投影图。source_*_front/back.png 是源网格中性材质渲染（如源网格本身为简化替身，仅证明该输入资源中的几何与姿态，不能称为游戏原版里昂模型）。

## 坐标与数值

为避免把“筒身上方”误读成只翻转 y，以源右腕为原点；沿现有重定向定义，右手局部 -X 为枪口方向，+Z 为武器上方。

首帧源左腕相对右腕（源右手局部 xyz，米）：

- Idle：[+0.271012, -0.121261, +0.144939]
- Walk：[+0.235456, -0.106867, +0.166892]
- Run：[+0.255009, -0.111624, +0.126523]

转换成规范武器轴（x = 源 y, y = 源 z, z = 源 x；枪口 -z）：

- Idle：[-0.121261, +0.144939, +0.271012]
- Walk：[-0.106867, +0.166892, +0.235456]
- Run：[-0.111624, +0.126523, +0.255009]

左腕处于右腕的后段、靠肩高位，而非枪口前端。上述坐标是腕关节，不是掌面接触点；也未包含 PF89 模型原点与右掌握把偏移，不可直接写进 left_grip。

完整周期左腕源局部 +X 范围：Idle 0.271012；Walk 0.234757–0.247569；Run 0.250060–0.262749 m。局部 +Z 范围：Idle 0.144939；Walk 0.166892–0.174780；Run 0.118792–0.126868 m。

首帧右肘武器上轴投影为 -0.167426/-0.172443/-0.177506 m；左肘则为 +0.136040/+0.161561/+0.100256 m。左臂与右臂明显不对称，左肘更靠左侧，左前臂横向回收，不能改成双臂共同向枪口端下托。

左手局部 +Y 与源武器上方向点积：Idle .945435；Walk .989386；Run .946581。它描述手骨轴，不应未经网格核对就命名为“掌面法线”。完整三轴和所有帧见 source_pose_samples.json。

## 现有姿态保留与被覆盖位置

1. tools/blender/retarget_re4_rocket.py 将源上身世界旋转经静止骨架标定输出 RocketUpperIdle/Walk/Run。保留源躯干/双臂/手腕旋转意图，但角色比例不同，且手指被目标 RifleAimingIdle 的固定手型替代。重定向不保证源世界腕位置或原武器接触点逐毫米一致。
2. rocket-motion.js installRocketMotions 在脊柱处消除步枪骨盆姿态差，保持步枪原下半身轨道；其设计并非把左手改成下托。
3. weapon-attachment.js:327 将普通持筒动作 support_pose_weight 设为 1；:330 加 carry_offset_body_m；fitRocketCarryReach 可继续抬筒改变位置；:400 solveArm('Right') 在重定向之后解右臂。
4. 同文件 :437–447 根据 left_grip、left_hand_quaternion_weapon、left_palm_offset_native 构造左腕目标，并用 solveLeftArm 权重 1 解左臂，实质覆盖源左臂和腕方向；后续手指逻辑另行覆盖手型。即使源 GLB 正确，此运行时步骤也能把手拉回错误下端。
5. 上述行号针对此次读取的 diandian-classic-motion-lab/weapon-attachment.js；后续修改会改变行号。

## 可执行校准顺序

1. 在关闭运行时握持修正的源重定向姿态下记录左右腕、掌偏移、肘点、胸坐标。以该结果为姿态基准，不以 R39 通过的接触误差为动作正确依据。
2. 保持原右手与筒体斜持关系，在源左掌附近选择 PF89 靠肩高位的后段（规范枪局部 +z）；参考本次实测的 +.17 至 +.22 m 候选区，再验证模型真实接触表面。
3. 从源重定向左腕 quaternion 反算 weapon-local 手腕朝向；对左右角色分别标定。不要沿用下托手型后只将 left_grip.y 翻正。
4. 用源左肘方向作为 IK 极向参考，保留左前臂横向回收和右肘低位关系。仅消除比例差和接触误差，不用大幅强制外展/前推把源动作改成其他动作。
5. 左手手指需根据 PF89 真实筒面重塑，并清楚说明为适配手型，不是原里昂手指动画。
6. 全周期检查 Idle/Walk/Run 三动作、两个角色的左掌后段位置、掌面方向、手指贴合、肘位与穿模；同时检查取出末帧、举筒初帧进入该姿态的连续性。

## 参考图目视复核

已查看 source_Idle_front.png 与 source_Idle_back.png：原输入网格确为里昂外形的低多边形蒙皮；左手抬在右肩/面颊附近的高位，左前臂斜向上回收，右手在腹部前方低位。没有原火箭筒网格，因此图中不能直接证明某根手指落在筒面哪条接缝。源手部几何和 22 骨结构也不足以提供精细包覆筒身的手指动画。R40 应复用这一高低手布局和腕向，同时另做与 PF89 筒径相符的手指适配。

RocketUpper 轨道保真结论来自生成链路与运行时覆盖代码核对，并非本报告额外实施了全部 GLB 四元数的逐帧数值回归；源 FBX 数值则是本次 Blender 实测。避免把生成算法意图夸大为已完成的数值一致性验证。
